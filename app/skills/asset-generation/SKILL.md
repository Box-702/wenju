# 生成资产：先问，再做

生成资产（定妆照 / 场景图 / 音色）**要花钱，而且会写进作品**。
所以流程是「问清楚 → 复述给用户 → 等点头 → 生成 → 汇报」，
不是「听到要生成就跑」。

## 一、先问清楚（一次问完，别挤牙膏）

1. **给谁生成**：哪些角色？哪些场景？
   —— 把作品里已有的角色/场景**列出来让用户勾**，不要自己挑。
2. **画面要求**（定妆照 / 场景图）：每个对象的具体要求——
   年龄、体型、发型、服装、气质、姿态、光线、画风上的补充。
   用户没写就问；**风格指南里的锚是默认，不是用户的决定**，别拿来当要求回填。
3. **声音描述**（音色）：音色高低、语速、年龄感、情绪、是否有口音。

已经有的东西先问一句：角色已有定妆照 / 已有音色 →「覆盖还是保留？」。

## 二、复述 + 等确认

把下面这张清单给用户看，等他说「就这样」：

```
要生成：孔乙己、掌柜
画面要求：
  孔乙己 — 三十五岁男性，深灰长衫，眼神疲惫，右手微颤
  掌柜  — 五十岁，胖，圆脸，棕色马褂，笑容油滑
音色（如果也要）：低沉沙哑的中年男声，语速偏慢
```

用户改了就改，改完再问一次。**没确认不要生成。**

## 三、生成

- **定妆照 / 场景图**：`generate_reference_assets(project_id, notes)`
  - `notes` 每行一条：`名字: 要求`（名字用角色名/场景名，或 id）。
  - 要求会拼进该对象自己的 prompt；没写到的对象按风格指南的锚生成。
- **音色**：`clone_voice(project_id, character, sample_asset_id, description, name)`
  - `sample_asset_id` 是资产库里那段样本音频的 id——先让用户在资产库「导入」里上传音频，
    再把 id 传进来（不要让模型自己编 id）。
  - `description` 是用户写的声音描述，会作为克隆时的参考文本。

一次只生成用户确认过的那一批；不要顺手多生成几个。

## 四、生成完要说的

- 生成了哪些、质检过没过（定妆照会过视觉模型质检）。
- 定妆照生成后提醒：**它会回填到所有提到该角色的镜头**（这正是它锁一致性的方式）。
- 音色生成后提醒：之后配音就用它，可以在资产库里试听或换。

## 硬规矩

1. **不替用户决定**：角色多的时候必须列清单让用户勾。
2. **不跳过确认**：没确认就生成 = 花钱 + 覆盖已有资产。
3. **不越界**：只生成用户点名的那几个。
4. **诚实汇报**：质检没过、被拒、失败，都要如实说，不要说「已生成」了事。
