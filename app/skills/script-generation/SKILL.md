# 初稿生成流程

## 开始前

- 先检查当前作品和原文是否存在；没有作品时先问清作品标题与原文，再创建。
- 生成方向、集数、单集时长、视觉风格或画幅存在未决分叉时，用 `ask_user_choice` 一次问清；不要自行替作者决定。
- **原文是文言文/半文言时（如《聊斋志异》《史记》、唐宋传奇；特征：之乎者也、单字词多、少现代口语），必须先问台词语言**：全部白话 / 保留文言 / 混合（旁白与日常白话，仪式、唱词保留古句）。不要直接生成；确认后把选择**同时带进 `plan_story(dialogue_style=…)` 和 `generate_script(dialogue_style=…)`**——提案里引用的关键台词也要按这个语体转述。工具不传这个参数会拒绝生成。
- 用户明确说「直接生成 / 别问了」时，沿用已给信息推进，并记下这次选择。
- 同一轮第一次执行生成前先加载本技能。短篇没有章节地图也可以生成；原文超过约 1.4 万字时，还必须先加载 `novel-serial` 并走章节地图与选段流程。
- 原文缺失或读取失败时先说明缺什么，不要用示例内容冒充用户原文。

## 先分集提案，再写剧本（硬流程）

- **第一次生成前必须先调用 `plan_story`**：读原文产出「理解卡 + 分集提案」。
  短篇也要做——至少 1 集；不要因为原文短就直接开写。
- 把工具返回的理解卡原文给用户看：故事内核、核心冲突、人物、关键事件数、
  每集标题/钩子/目标秒数。**不要只报一句「提案好了」**。
- 只有用户明确确认（「可以」「就按这个」「确认」）后，才调用 `confirm_story_plan`；
  不要替用户拍板，也不要在待确认状态直接 `generate_script`。
- 用户要改集数、钩子或事件归属时，带 `episodes` / `notes` 重新调用 `plan_story`，
  改完再确认。已确认的台词语体也要一起带（`dialogue_style`）。
- 确认后再 `generate_script`：它会读取已确认提案，按集扩写，事件清单是底线。
- 用户明确说「不要提案，直接生成」时才可跳过；跳过时在回复里说明这次没有分集大纲。

## 执行与汇报

- 只通过 `generate_script` 生成；工具返回前不得声称已生成、不得编造版本号或场次数。
- 生成后按工具返回说明版本、场次、人物数、实际覆盖的原文范围和仍需作者确认的事项。
- 生成失败时复述可验证的错误与下一步，不要通过重复调用掩盖失败。
- 用户要求改已有剧本时走 `run_adaptation` 提案与审阅流程，不要把重生成当作静默覆盖。
