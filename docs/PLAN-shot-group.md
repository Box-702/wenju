# PLAN-shot-group —— 镜头组架构 + Blender 白模约束层

> 2026-11-12 起草。触发：v3 观感复盘（83 秒重复一个动作）+ 三路厂商调研
> （MiniMax / Seedance+可灵官方文档 + B 站 13 篇创作者实践）。
> 技能/审计层已先行改完（镜头组语法、台词官方句式、故意不完美、轴线，
> 见 6c2eb21 与其后提交）；本文档是**数据与链路层**的改造方案。
> 决策依据见 D-45、DEVELOPMENT 5.37/5.38。

## 〇、一句话目标

把「一次生成 = 一个孤立镜头」改为「**一次生成 = 一个镜头组**（2-4 个机位、
≤15 秒、组内切镜不漂移）」，并让 Blender 白模成为组的**行为约束层**：
文本 AI 生成白模动画定粗动作与位置关系，既供人审，又反哺视频提示词——
减少抽奖和规范行为是同一件事，不是两个环节。

## 一、为什么（证据链）

1. 厂商原生支持：MiniMax H3 官方增强提示词就是 `[Shot 1]…[Shot 2] At 00:02.800,
   the camera cuts to…`；可灵有显式 `shot n,m,words` API（1-6 镜、秒数和=duration）；
   Seedance 认 `镜头1：…镜头2：…`。**同一次采样内换机位不漂移**——漂移只发生在跨生成。
2. 我们的旧规则「禁止覆盖式拍摄」把正反打连同解法一起砍了 → 每镜一个微动作
   循环 → v3 的 PPT 感。用户口述的排钱戏三机位（孔乙己→他视角看钱→掌柜过肩）
   正是官方语法一次能生成的东西。
3. 成本同向：一次生成 10-15s 比 3 次各 4-5s 便宜（输入参考秒数摊薄、
   接力锚减半），且打回单位从"镜"变"组"后，重 roll 一次修好整段戏。

## 二、数据模型（最小侵入）

**不新建实体，Shot 上加三个字段**（组是镜头的属性，不是新对象）：

```python
# app/domain.py::Shot 新增
group_id: str = ""        # 同组镜头共享；"" = 单镜自成一组（旧行为）
group_index: int = 0      # 组内序号（0 起），决定时间轴顺序
# duration_sec 复用：组内每机位的秒数；组总时长 = Σ，校验 ≤15
```

- 校验器新增：`group_id` 非空的镜头必须 order 连续、组总时长 4-15s、
  组内每机位 ≥1s、组内说话人不重叠（一镜一说话人升级为**一组一说话人/机位**）。
- 兼容：旧版本数据没有这三个字段 → 全部视为单镜组，链路行为与现在逐字节一致。
  **不做数据迁移**，新旧共存。

## 三、生成单位 = 组：链路改动点（按依赖顺序）

| 层 | 文件 | 改动 |
|---|---|---|
| 导演 | `crew/director.py` | 输出后按叙事高点分组建组（规则在 SKILL.md 已写：对峙/揭示/关键道具才成组）；`enforce_duration_budget` 的删镜改为**按组删**（整组一起删，防删半个戏） |
| DP | `crew/dp.py` | 组装时同组镜头的 prompt_body 拼成 `[Shot N] At 00:XX, cuts to…` 一条 video_prompt（时间戳由组内 duration 累加算出，**代码算不让模型算**——Seedance 官方明说精确时间模型不稳，我们只喂 MiniMax，它母语就是这个格式）；`strip_spoken_quotes` 白名单已就位 |
| 落库 | `store.py` | `VideoVersion.shots` 里带组字段即可（JSON 列，无 schema 迁移）；新增 `group_key(shot_dicts)` 辅助：把 shots 折叠成生成单元列表 |
| 提交 | `video/service.py` | `VideoJobCreate.shot_id` → 语义改为 **unit_id**（组 id 或单镜 id，字段名不动，claim key 的 intent 加 group 成员与各自时长）；`_auto_references` 的接力锚按组取（上一**组**尾镜成片）；`generate_batch` 的 `shot_ids` 换成 unit 列表 |
| 批次 | `video/batch.py` | 推进单位 = 组；`results` 键 = unit_id；UI 进度文案「镜」→「段」 |
| 质检 | `video/qa.py` | 抽帧数按组时长放大（15s 组抽 7-9 帧）；FAIL 时重 roll 整组；降级改写函数输入是**组提示词**，缺陷定位到机位段（「第 2 机位手指畸变」→ 只降级那一段的描写） |
| 成片 | `video/finalize.py` | clips 列表 = 组视频（时长实测校准逻辑不变，只是条目变少）；**配音时间轴**：`dialogue_at` 语义从"镜内秒"变"组内秒"，dubbing 的 `plan_dubbing` 按组起点累加——这是最容易错的地方，测试要重点锁 |
| UI | `VideoWorkbench.vue` | 镜头卡按组折叠显示（组内机位是卡内小节），批准按钮以组为单位；批准粒度变粗是刻意的：一次审一段戏 |

**不动的东西**：资产库、版本链、批准闸门语义（D-43）、TTS 后配为主
（模型自生语音仍不可信，组提示词里的台词是表演锚不是最终声音）。

## 四、Blender 白模 = 组的行为约束层（与打回不冲突，是同一层）

定位（用户 2026-11-12 明确）：**文本 AI 控制 Blender 生成白模动画，
规范每个镜头组的人物粗动作与位置关系，用来给视频模型"立规矩"+ 减少抽奖**。
它不是"打回的另一条路"，而是把打回要发现的问题**前置消灭**：

```
导演分组 → 【previz（可选）】→ DP 组提示词 → 批准 → 出片
              │
              ├─ ① LLM 按组生成 Blender Python（方块人 + 相机动画 + 走位）
              ├─ ② EEVEE 快渲：组时长秒数的白模视频 + 每机位关键帧静帧
              ├─ ③ 人审白模：改走位/砍机位/调相机（对话里说，Agent 改场景重渲）
              └─ ④ 反哺：白模关键帧静帧 → 组内各机位的构图锚/首帧参考；
                     相机路径与位置关系 → 写进组提示词的 spatial/camera_path 段
```

- **一致性红利**：白模静帧就是"这一帧画面长什么样"的确定答案，比文字描述
  强一个量级（社区共识「你没写的东西就等于没有」的终极解法）。
- **成本**：Blender 本地渲染 ¥0；关键帧图若走 MiniMax 生图 ¥0.14/张。
- **安全**：Blender MCP = 任意 Python，走 D-43 批准闸门（Agent 发起、用户确认）；
  渲染是后台任务 + 完成通知，不占对话线程。
- **降级**：Blender 未启动时该阶段整体跳过，如实提示，链路照常。
- 环境已就绪：Blender 5.2.2 便携版 + 官方 mcp 扩展 + blmcp 桥（2026-11-12 接通）。

## 六、风险清单

1. **组=更大赌注**：一次生成 15s，崩了损失 15s 的钱——用 S3 的 previz
   和「组只留给戏剧高点」压这个风险。
2. **配音对位**：组内时间轴与 TTS 排期是最容易错的一环（dubbing 的
   dialogue_at 语义变化），S2 必须有专项测试。
3. **MiniMax 方言独占**：组语法按 H3 的 `[Shot N]/At` 写；将来 Seedance
   A/B 胜出要换方言时，拼装函数按 provider 分支（可灵是 API 参数不是文本
   语法，Seedance 2.0 只认序号不认时间戳——已调研，接口留了形状）。
4. **evals 阈值联动**：DIR-10~13 是按单镜统计的，成组后"特写占比"要按
   **机位**算而不是按生成单元算，S1 同步改。
