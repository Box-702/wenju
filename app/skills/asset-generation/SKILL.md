# 生成资产：先问，再做

生成资产（定妆照 / 场景图 / 音色）**要花钱，而且会写进作品**。
所以流程是「问清楚 → 复述给用户 → 等点头 → 生成 → 汇报」，
不是「听到要生成就跑」。

## 一、先问清楚（一次问完，别挤牙膏）

1. **给谁生成**：哪些角色？哪些场景？
   —— 把作品里已有的角色/场景**列出来让用户勾**，不要自己挑。
2. **画面要求**（定妆照 / 场景图）：每个对象的具体要求——
   年龄、体型、发型、服装、气质、姿态、光线、画风上的补充。
   用户没写就问；**风格指南里的锚是默认，不是用户的决定**，别拿来当要求回填。
3. **声音描述**（音色）：音色高低、语速、年龄感、情绪、是否有口音。

已经有的东西先问一句：角色已有定妆照 / 已有音色 →「覆盖还是保留？」。

**这些不用问，问了就是打扰**：
- **画风**：作品已有既定画风就沿用；没定过就按项目默认走（写实），生成时在汇报里
  说明用的哪套。用户要改会自己说——不要让他先选一个画风才准开工。
- 能从角色名 / 剧本 / 风格指南推出来的（性别、年龄段、身份气质）：按推断写，
  汇报里注明「按推断」；只有**影响剧情走向**的信息缺失才值得问，
  「影响画面长什么样」的缺失选一个合理默认先做出来。

## 二、复述 + 等确认

把下面这张清单给用户看，等他说「就这样」：

```
要生成：孔乙己、掌柜
画面要求：
  孔乙己 — 三十五岁男性，深灰长衫，眼神疲惫，右手微颤
  掌柜  — 五十岁，胖，圆脸，棕色马褂，笑容油滑
音色（如果也要）：低沉沙哑的中年男声，语速偏慢
```

用户改了就改，改完再问一次。**没确认不要生成。**

## 三、生成

- **定妆照 / 场景图**：`generate_reference_assets(project_id, notes, entities)`
  - `entities`：**点名范围**（逗号分隔的角色名/场景名）——只生成点名的那几个，
    未点名的已有定妆图原样保留；留空才等于全部。确认清单里有谁，这里就填谁。
  - `notes` 每行一条：`名字: 要求`（名字用角色名/场景名，或 id）。
  - 要求会拼进该对象自己的 prompt；点名了但没写要求的对象按风格指南的锚生成。
  - 名单里的名字都对不上角色/场景时，工具会**什么都不生成**并如实报告——
    不要改成不传 entities 来「试试」，那会变成全量重生成（花用户的钱）。
- **音色**：`clone_voice(project_id, character, sample_asset_id, description, name)`
  - `sample_asset_id` 是资产库里那段样本音频的 id——用 `list_assets(project_id, kind="audio")`
    查真实 id（用户没上传就先请他在资产库「导入」里上传）；不要让模型自己编 id。
    样本必须属于本项目，跨项目的 id 会被拒绝。
  - `description` 是用户写的声音描述，会作为克隆时的参考文本。

一次只生成用户确认过的那一批；不要顺手多生成几个。

## 四、生成完要说的

- 生成了哪些、质检过没过（定妆照会过视觉模型质检：构图、面孔、**画风与项目一致**）。
- 生成完提醒用户在资产库逐张看一眼：质检只拦致命问题，气质合不合用户的意
  要人来定；不满意就让他说「掌柜的重生成，要凶一点」，用 notes 带要求重跑那一个。
- 定妆照生成后提醒：**它会回填到所有提到该角色的镜头**（这正是它锁一致性的方式）。
- 音色生成后提醒：之后配音就用它，可以在资产库里试听或换。

## 硬规矩

1. **不替用户决定，也不零碎地问**：要生成多个资产时，一次列清单让用户勾选/取消，
   一次确认完。不要一个一个问「要生成谁？」「什么风格？」——反复追问既拖时间，
   又让用户失去对整体计划的掌控。要问就一次问完，用清单。
2. **不跳过确认**：没确认就生成 = 花钱 + 覆盖已有资产。
   用户说「直接生成」「别问我了」「按默认来」——这些只允许你省略重复的自然语言追问，
   **不能跳过确认**。确认是用户的正式决定。
3. **不越界**：只生成用户点名的那几个。
4. **诚实汇报**：质检没过、被拒、失败，都要如实说，不要说「已生成」了事。
