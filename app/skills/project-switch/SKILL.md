# 切换作品（D-77）

「换作品」= 把**这段对话**挪到另一部作品下继续聊。会话 id 不变，历史一起
跟着走；切完之后界面不跳，用户看到的还是同一条对话线，只是内容归属换了。

这件事以前是输入框里的一个下拉按钮，点一下直接改前端状态。现在它是**技能**：
用户在对话里引用「切换作品」，你按下面的流程执行。

## 为什么换作品要走对话，不走按钮

作品归属是这段对话的**事实**：你说「把这份稿子改一下」，指的是当前作品里的
那份稿子；Agent 也得知道自己在哪部作品下干活。切换动作留在对话里才有据可查——
用户回看历史，能看见「我什么时候换到了《孔乙己》」。按钮那种无声的切换，
换完谁都说不清现在在讲哪部作品。

## 执行流程（三步，顺序就是纪律）

1. **对齐剧名**。用户说「切到孔乙己」时，先用 `list_projects` 拿到真实清单，
   再决定切哪一部。**不要凭记忆报剧名**——作品列表是会变的（新建的、删掉的、
   同名的），凭记忆切错一部，前面的对话就白聊了。
   · 用户已经给了确切剧名、清单里也只有它 → 直接进第 3 步。
   · 用户只说「换一部」「换到另一部」或者你只匹配到多部 → 把候选列给用户
     （剧名 + 一句话简介），问一句「要哪一部？」，**别自己挑**。
   · 一部都没有 → 直接说现在还没有作品，让用户先导入或新建。

2. **确认歧义**。`switch_project` 命中多部或一部都没命中时，它会回你候选。
   这时候你的任务是**把候选转述给用户**，让他拍板，不是自己再猜一轮。
   用户回了名字（哪怕只是半个字），再调一次 `switch_project` 即可。

3. **切换并回执**。`switch_project` 成功后会回「已切到《X》」。你照着这句话
   回给用户即可，**不要顺手开始生成任何内容**——用户说的是换作品，不是
   「换作品并立刻出片」。等用户给下一步指令。

## 硬规矩

- **一次只切一部**。不要连续调两次 `switch_project` 去「试探」切哪一部——
  那会把对话挂到错误的作品上。匹配不确定就问。
- **切换不产生内容**。切完只回执，别顺手生成初稿、别拆镜、别跑流水线。
  用户在这部作品下要做什么，是下一句话的事。
- **别替用户做「换到最近一部」**。「最近使用」是界面排序，不是用户的意思。
- 换完之后当前作品就是新作品，后续工具调用**不再传旧的 project_id**——
  工具会自己兜底到当前作品。

## 失败处理

- `switch_project` 说「没有找到叫 X 的作品」→ 把现有作品列给用户，让他挑。
- 工具报「切换失败」→ 老实说没切成，问用户要不要重试，别当成已经切了。
- 用户中途改主意（"算了不换了"）→ 什么都别调，直接接他的话。

# 相关工具

- `list_projects`：列出全部作品（剧名、id、版本数、状态）。对齐剧名用。
- `switch_project`：把当前对话改挂到目标作品上（历史跟着走）。
