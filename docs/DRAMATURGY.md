# 戏剧结构方法论落地说明

> 方法论来源：[smixs/visual-skills](https://github.com/smixs/visual-skills)（CC BY 4.0 · Serge Shima）
> 原始整理稿：《AIGC 视觉内容提示词方法论》（2026-09-22）

## 核心思想

**先戏剧，后语法**——模型语法在戏剧结构到位之前一文不值。结构对了，模型才有
东西可渲染；结构错了，再正确的镜头语言也救不了这个镜头。普通 prompt 是四个形容
词加零个事实；本链路的 prompt 是「一个情绪 · 三个镜头 · 三个细节 · 一个最终画面」。

## 落地位置

| 方法论概念 | 落地模块 | 说明 |
|---|---|---|
| 三工作规则（改情绪/推进/施压） | `Shot.function` + 导演系统提示词 | 一镜必做一件事，写不出 function 的镜头是壁纸，critique 循环强制重拆 |
| 细节律（三细节） | `dramaturgy.three_details` | 环境压力 / 身体微动作 / 声音锚点·视觉母题；零细节=废镜头，一细节=单薄 |
| 五锚点（One-anchor） | `SceneAnchors` + 导演 JSON 输出 | 每场只承诺：一个情绪、一个母题、一个物体、一次破裂、一个最终画面 |
| 最终画面规则（U11） | `Shot.final_frame` + DP 拼装兜底 | 视频模型把最后一帧当情绪目的地；body 必须以结束帧收尾，漏写自动补 |
| 运镜动机（Fincher 法则） | 导演系统提示词 | camera_path 起笔写「什么变了」，答不出就 static |
| 节奏阶梯 | 导演系统提示词 | 同场时长走「长→渐短→冲击」阶梯，最大冲击前一镜放最慢 |
| 场景公式 | 导演系统提示词 | desire/obstacle/geometry/gaze/rhythm 五问；gaze = 每镜 subject 是唯一焦点 |
| 空洞占位词禁用 | `dramaturgy.find_slop_words` / `strip_slop` | 电影感/epic/masterpiece 等渲染不出来的词：整段占位机械剥除，混写句审计告警 |
| 否定句禁用 | `dramaturgy.find_negations` | 模型会把被否定的动作画出来；引号内的实体招牌文字不误伤 |
| 情绪只写身体（U3） | DP body 规则 11 | 情绪名词翻译成 2-4 个可观察身体线索，多了像演技过火 |
| 写实人物公式（反 AI 脸） | 美术指导系统提示词 | 肤色肤质+3-4 个面部细节+视线神态；气质词渲染不出来 |
| 环境会表演（黑泽明） | 美术指导系统提示词 | 每个地点写一个承载情绪的「环境压力」细节 |
| 出厂前双重审计 | `dramaturgy.audit_breakdowns` / `audit_video_prompt` | 第一道在导演侧回喂 critique；第二道写进 `Shot.prompt_audit` 供人工审阅 |

## 数据流

```
导演拆解 ──→ audit_breakdowns（戏剧结构检查）──→ critique 循环重拆（有界 3 次）
   │
   └─ Shot.function / final_frame、SceneAnchors 随版本落库
                    │
摄影指导 ──→ body 写作规则（十三条）+ 台词/运镜/占位词机械兜底 + final_frame 兜底
   │
   └─ audit_video_prompt → Shot.prompt_audit 落库
                    │
人工审阅 ──→ 审阅面板展示逐镜审计提醒（PromptEditor / ShotList 角标）
   │
   └─ PUT /prompts/review 保存时服务端刷新 prompt_audit
```

## 设计约束

- 审计只提醒、不拦截（沿用成片质检的教训：把小瑕疵也算 FAIL 会让告警脱敏）；
- 词库判定是保守的：命中算有，零命中才报「废镜头」；
- 机械剥除（台词引用、整段占位词）只做语法安全的子集，其余交给写作规则在源头避免。

## 2026-11-12 外部校验修订（写作规则 11 条 → 13 条 + 镜头组语法）

> 方法论第一次系统性「对外验证」：此前十一条规则全部由我们自己的实测
> 归纳（v1-v3 孔乙己、13号巷），这次发现**两条核心规则被厂商官方文档直接推翻**。

**遇到的问题**：v3 全片（24 镜横屏 Lite）观感反而不如 v1——「83 秒全在重复一个
3-4 秒的动作」；对话戏全是正脸怼脸、无空间关系；音轨是模型自生的含混假语音。

**参考了什么**（三路并行调研，来源全部留档在 PLAN-shot-group 第六节）：
- MiniMax 官方：H3-Context-IR 增强提示词的官方格式就是 `[Shot 1]…[Shot 2] At
  00:02.800, the camera cuts to…` + `overall_soundscape` + `non_diegetic_music`
  三段（platform.minimaxi.com/docs）；治 AI 味的官方示范是「拍摄设备瑕疵」
  （手抖/对焦犹豫/曝光波动）；台词官方句式 `角色说话：「…」`。
- 火山方舟 Seedance 2.0/2.5 官方提示词指南：`镜头1：…镜头2：…`；2.0 不响应
  精确时间戳（2.5 才响应）；音画符号表（）音乐 <>音效 {}台词 【】字幕。
- 可灵官方：显式多镜头 API `shot n,m,words;`（1-6 镜、每镜秒数之和=duration）。
- B 站 13 篇创作者实践（含 4 篇带软广打折看）：正反打难点在串脸与轴线（屏幕
  左右是机位属性不是角色身份）；双人戏互斥特征 ≥3 识别点；「批量出静帧→人挑图
  →图生视频」是最省返工的人工闸；全片无人自动跑完是行业公认的亏损原因之一。

**推翻了什么、怎么改的**：
1. ~~禁止覆盖式拍摄/正反打~~ → **镜头组**：多机位打包进一次生成（同一次采样
   内换机位不漂移，漂移只发生在跨生成）。导演 SKILL.md 重写该节，组只留给
   戏剧高点（对峙/揭示/关键道具），组=2-4 机位 ≤15s。数据层改造见
   PLAN-shot-group（S1-S4）。
2. ~~台词绝不进提示词~~ → 官方句式 `角色说话：「…」` 进提示词锚表演节奏，
   成片声音仍以 TTS 后配为准（模型自生语音不可信这条没变）；
   `strip_spoken_quotes` 机械兜底加白名单——旧式「说道：『…』」照剥，
   官方句式放行。
3. 新增规则 12「故意不完美」（治 AI 味：每 2-3 镜一处手持晃动/失焦回焦/曝光起伏）。
4. 新增规则 13「轴线写死屏幕方位 + 双人互斥特征」（社区串脸排查法）。
5. 审计器同步升级：DIR-10~13 全片级 critical（特写>40%/静态>75%/零wide/
   动作不足 3 段）——回喂管不住的进确定性层，与片长闸门同一原理。

**原理与思路（可复用的方法论）**：
- **闭门实测归纳出的规则，要定期拿厂商官方文档对照**——我们的规则描述的是
  「我们踩过的坑」，官方文档描述的是「模型的能力边界」；把坑的解法（禁止）
  当成能力的边界（不支持），就会砍掉模型本来擅长的东西。
- **规则有钟摆效应**：每条「防过载」的上限规则会诱发模型贴地板（防穿模→
  静止→PPT），必须配对偶的下限检查。
- **改规则先改调研，再改文本，最后改数据**——技能文本当天可改（¥0），
  数据模型走 PLAN-shot-group 分期（每期独立可停）。

> 【2026-11-13 更正】上文第 2 条「成片声音仍以 TTS 后配为准」已被当天晚些时候的
> 实测推翻：孔乙己 native 成片因台词被判据剥光而**完全没有台词人声**。现行口径：
> native（默认）= 官方句式台词就是成片人声；TTS 只在 audio_mode=dub 时接管。
> 判据同步放宽：引号前挂冒号即官方句式（不再字面认「说话：」）。见 D-50 / 5.44-5.46。

## 2026-11-13 运镜词表扩充（用户提供 12 技法 → 导演选镜映射 + 摄影句式表）

> 用户给了一份「镜头方法/适用情况/可复制表达」三段式运镜资料（推进、拉远、
> 横摇、向上摇、甩镜、跟拍、手持、环绕、急推拉变焦、滑动变焦、子弹时间、慢动作），
> 问是否采纳进 skill。结论：**采纳，但不是照单全收——按 AI 生成的可行性过滤**。

**遇到的问题**：果园 v3 看片反馈里运镜单调；导演技能已有 5 个运镜词
（缓推/拉远/平移/轻摇/环绕）但只有「是什么」没有「怎么写」——摄影指导拿到
camera_type 后靠自由发挥写轨迹，句式质量不稳定。

**参考了什么**：用户词表本身（三段式结构就是好模板：技法→戏剧意图→可复制句式）；
与 D-46 三源调研档案交叉（MiniMax 官方示范、Seedance 官方指南、社区实践）。

**怎么采纳的（过滤规则）**：
1. **导演 SKILL.md**（选镜层）：新增 tilt up/甩镜/急推拉变焦 三个「意图→技法」
   映射（逐层揭示/突然转场/揭示反转），每个词都绑定戏剧意图而不是效果——
   Fincher 法则的延伸：先答「这一镜在讲什么」再选运镜。
2. **摄影 SKILL.md zh/en 同步**（写词层）：11 条「可复制句式」骨架
   （起点→轨迹→落点→速度节律，四件齐全），直接可抄进 prompt_body。
   这是摄影技能第一次有句式模板——此前只有原则没有例子。
3. **AI 可行性过滤，两处降级**：
   - **子弹时间默认不用**（定格主体+镜头绕行 = AI 端最容易崩的组合：定格人脸
     被重绘、背景扭曲），词表保留但标注禁用，非用不可改成「时间仿佛慢下来」；
   - **滑动变焦是「一镜一运镜」铁律的唯一例外**：它本质是两种运动（推近+拉广），
     必须写成一句连贯轨迹，拆开写模型就退化成普通推进——铁律条同步加了例外声明；
   - 慢动作/子弹时间定性为**节律不是机位运动**：不占 camera_type，写进
     action/path 速度节律，一镜最多一处放慢。
4. **与既有规则对齐**：甩镜补了「途中短暂模糊→落点稳焦」的写法要求（呼应
   规则 12 故意不完美——快速运镜后的失焦合焦正是官方示范的拍摄瑕疵）；
   环绕维持「慎用」原判（AI 绕半圈崩结构是 v2 实测教训，不因词表收录而放宽）。

**原理与思路**：外部运镜资料的价值排序是「句式>映射>词表」——词表我们本来
就有大半，戏剧意图映射补了 3 个空位，真正缺的是**可复制的句式骨架**
（模型只看得懂「机位沿桌子中轴靠近、末段减速」，看不懂「推进」两个字）。
采纳任何外部清单前先过 AI 可行性筛：真人影视的技法名词直接进提示词，
等于请模型表演它不会的东西。
